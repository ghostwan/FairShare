# AGENTS.md

Operational guide for AI coding agents (Claude, GPT, …) working on this
repository. Read this in full before doing anything.

  a per-item receipt scanner.

## Hard rules

1. **All commit messages MUST be written in English.** No exceptions.
   The interactive conversation can be in French; commits, code
   comments, and documentation files (`README.md`, `app/docs/**`) are
   English.
2. **The commit author must remain `Ghostwan <ghostwan@gmail.com>`.**
   Never alter `user.name` / `user.email`. Never add `Co-authored-by`
   trailers or "Generated by …" footers. The owner uses this identity
   for his professional work.
3. **Never commit secrets.** `local.properties` is gitignored and
   contains the Gemini API key — leave it alone. If you see a key
   pasted in chat or in a log, do not echo it back into a file.
4. **Never force-push `master` / `main`.** Force-pushing the `claude`
   branch is fine (`git push --force-with-lease origin claude`) since
   the owner reviews and merges manually.
5. **Always run `./gradlew :app:testDebugUnitTest` before committing
   a parser change.** All 23 tests must stay green. If you add a fix
   you should add a regression test.
6. **Reply in French in chat by default.** The owner is French. Code,
   commits, and docs stay English.

## Stack & architecture

- Kotlin + Jetpack Compose (Material 3), single-Activity.
- Clean Architecture, strict: `domain/` ⇢ pure Kotlin (no Android),
  `data/` ⇢ Room + repository impls + OCR engines, `presentation/`
  ⇢ Compose + ViewModels.
- Hilt for DI. Two `ReceiptParser` implementations live behind the
  qualifiers `@MlKit` (default, offline) and `@Gemini` (REST fallback).
- Money is always stored as `Long` cents. Default currency is EUR.
- Persistence: Room, with DataStore for settings (Gemini key + model).
- Networking: OkHttp + kotlinx-serialization (only used by Gemini).

## Workflow for a new OCR bug (`bug-NN`)

The owner will hand you a receipt photo that the parser gets wrong.
Follow this exact loop:

1. **Capture the dump.** Owner scans the receipt on his device while
   `adb logcat -d -s 'ReceiptOCR:*'` is being watched. Save the dump as
   `app/docs/bug-receipts/bug-NN-<name>/ocr.log` and copy it as a
   fixture: `app/src/test/resources/receipts/bug-NN-<name>.log`.
2. **Add the artefacts in `app/docs/bug-receipts/bug-NN-<name>/`:**
   - `bug.png` — receipt photo
   - `result-before-fix.png` — screenshot of the broken parse
   - `result-after-ai.png` — screenshot of the Gemini fallback (often
     the ground truth)
   - `expected.md` — symptoms, geometric diagnosis, proposed fix,
     expected result table
3. **Write the regression test FIRST**, in
   `MlKitReceiptParserFixtureTest.kt`. Use `loadFixture()`. Assert on
   item count, sum of `priceCents`, and a few label substrings. Make
   sure it fails for the right reason before writing the fix.
4. **Fix `MlKitReceiptParser.kt`.** Do not regress any existing test.
   If a synthetic test (rowHeight=30) and a real fixture (medianHeight
   ≈ 80) disagree, prefer ratios that work on both rather than
   hardcoded thresholds.
5. **Run `./gradlew :app:testDebugUnitTest`**, fix until all 23+ tests
   pass.
6. **Build, install, ask the owner to re-scan.** `./run.sh debug`,
   then `./screenshot.sh app/docs/bug-receipts/bug-NN-<name>/result.png`
   and `adb logcat -d -s 'ReceiptOCR:*' > .../ocr-after-fix.log`.
7. **Update `expected.md`** with the actual labels you got. They will
   not always match the ideal — that's fine if the price total and the
   item count are right (OCR misreads like `T-S!IRT` are outside the
   parser's scope).
8. **Commit in English**, push to `claude` with
   `git push origin claude` (or `--force-with-lease` if you amended).

## Parser quick-reference (current state, post-bug-04)

Pipeline in `MlKitReceiptParser.extractItems`:

```
tokens
  → splitStuckPriceTokens          # "BRUT7,50" → ["BRUT", "7,50"]
  → dropDuplicatePriceColumns      # cluster prices by x, label-alignment
                                   #   score wins, else size-based
  → row clustering                 # anchor-based, tolerance medianHeight×0.6
  → mergeMultiLineLabels           # up-walk label rows into a price row
                                   #   (gap < medianHeight × 1.3, requires
                                   #   a real label token); down-walk
                                   #   drops SKU-like rows
  → rowToItems                     # band-sorted labels, filter currency,
                                   #   strip tax-code letter, quantity
                                   #   extraction, drop noise patterns
```

Each bullet has a corresponding bug fixture. Touching one stage without
re-running all 4 fixtures is how regressions get introduced — always
run the full test suite.

## Debugging tips

- Temporarily wrap a `println` in `if (System.getenv("OCR_DEBUG") == "1")`
  inside the parser; run a single test with `OCR_DEBUG=1 ./gradlew
  :app:testDebugUnitTest --tests "…specific test…"`. The output is in
  `<system-out>` of the generated XML report at
  `app/build/test-results/testDebugUnitTest/TEST-*.xml`.
- Remove the prints before committing.
- `ReceiptOCR` is the only Logcat tag that dumps token geometry. Pair
  with `screenshot.sh` to compare parser output vs receipt image.
- For Gemini issues: `GeminiReceiptParser` logs the model + key length +
  prefix/suffix (never the full key) under tag `GeminiReceiptParser`.
